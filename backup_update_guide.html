This document outlines the standard operational procedures for securing corporate data via local database backups and applying software updates safely without disrupting operations.

💡 Control Center Shortcut: Double-click the scripts/Jomish_Suite_Launcher.bat utility in the application folder to access a guided terminal menu containing automated database backup and server health checks.

📂 Database Backup Procedures

🗄️ Option A: SQLite (Standalone)

Standalone deployments run on an embedded SQLite database. Backing up SQLite simply involves copying the database file.

  1. Open the Jomish Suite launcher (Option 7) or execute in Node:
node tools/backup.js [dest-folder]

If no destination folder is supplied, backups are timestamped and saved in the data/backups/ folder.

🐳 Option B: PostgreSQL (Docker)

Enterprise deployments utilize a PostgreSQL server inside a Docker container. Backups require a database dump.

  1. Launch the Control Center batch file.
  2. Press 7 to run the automated database dump script.

This runs the native export command under the hood, writing the output SQL file:

docker exec jomish-db pg_dump ...
⚠️ Crucial Security Action: After creating a backup, copy the generated .db and .json (or .sql) files immediately to a separate physical USB flash drive or secure cloud storage.

🔄 Database Restore Procedures

If a hardware failure occurs, restore your database by running the restore engine script. This automatically creates a safety copy of the current state before replacing it.

  1. Shutdown the server and run the restore script by passing the path of your backup file:
node tools/restore.js C:\path\to\your_backup.db
✅ Safety Guarantee: The restore engine saves your current database state as a safety duplicate (e.g. jomish_pre_restore_timestamp.db) before applying the backup.

🚀 System Update Procedures

Updates are delivered in two formats depending on the architecture: Container updates (Docker) or Schema updates (JavaScript). Both preserve your business transaction history.

🐳 1. Secure Container Updates (Docker Fortress)

To update the server application while maintaining safe sandboxed rules:

  1. Download the encrypted update archive (update.tar) provided by Jomish.
  2. Place update.tar directly in the project root folder.
  3. Double-click the scripts/Update_Jomish_Suite.bat utility.

The system will automatically:

  • Validate that the ports are clear.
  • Decommission the old running container.
  • Load the new image and launch the container with secure --read-only flags.

⚡ 2. Schema and Migrations Updates (JavaScript)

If the update includes new tables, fields, or database index improvements, run the schema update engine:

  1. Download the schema migration files and place them in the updates/ directory.
  2. Execute the update engine via the terminal:
node tools/apply-update.js

This checks all pending updates, applies them sequentially to your database, and bumps the system metadata version, ensuring **zero data loss**.

📋 Best Practices Checklist

🔒 Database Safeguards

  • Create local backups weekly.
  • Keep backups on a separate flash drive.
  • Run a system health check prior to restoring.
  • Double check database integrity before deleting backups.

⚙️ Update Rules

  • Always create a backup **before** updating.
  • Ensure Docker Desktop is running before launching container updates.
  • Review the update console log for any schema conflicts.
